# 智能采集质量管控平台

面向数据采集团队的质量管控与效率优化平台。覆盖采集任务编排、抓取结果校验、采集链路监控、数据格式转换、去重比对、异常重试、采集审计与合规管理的完整采集质控链路。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 发布前联合门禁

采集合规规则的「发布规则」不是一次简单状态流转，而是依次核对下面这条数据链：

1. **站点准入**：站点域名（归一成 host 后作为判定主键）、协议标识（仅 http/https）、
   访问间隔（不低于站点访问阈值，阈值 = 站点默认值与同站点已生效规则的最大间隔取高者）、
   并发上限（1~32 的整数）、请求头模板（每行 `名称: 值` 且必须含 `User-Agent`）。
2. **代理核对**：按站点列出代理节点，只有「已启用 + 冷却结束 + 可用率 ≥ 90%」的节点可用；
   可用额度不足并发上限时不允许发布。
3. **计划影响**：列出使用该站点的采集计划；采集间隔低于规则访问间隔即视为冲突，
   冲突未消除前不允许发布。发布通过后，这些计划才会获得启动资格（可排班）。

任一条不满足时规则不会生效，只落一份「待调整清单」（`422`），清单逐条给出范围、
条件、要求、实测与调整建议；规则详情、计划影响清单与代理可用量三处读同一份锁定台账。

并发口径：

- 同一规则同一版本只允许一份发布结果落库，后续请求返回 `409`；版本号由规则字段指纹生成。
- 两条规则并发申请同一批代理额度时，先拿到锁的请求先锁定，后到的请求在额度判定里被拦下。
- 规则废弃时释放额度，受其约束的计划同步标记「已失效/已阻断」，运行中的计划转为「已暂停」。

相关接口：

- `GET /api/compliance/{id}/publish-gate`：发布前预检（只计算不落库）。
- `GET /api/compliance/{id}/proxy-availability`：按站点列出代理可用节点与排除原因。
- `GET /api/proxy/quota-summary`：代理清单入口的额度汇总（容量/锁定/可用）。
- `PUT /api/compliance/{id}`：按待调整清单修正草稿或待审批规则。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
